请将这两路第一视角合成为一个同屏同步的复盘大屏，以 `changsheng.mp4` 的播放时间为成片和数据的共同时间基准，完整保留对局至水晶告破，并标明各路画面的队伍、选手和英雄。

请在大屏中叠加实时更新的两名选手**对敌方英雄累计输出排行榜**和**承受敌方英雄累计伤害排行榜**，用动态条形图展示两人的累计数值（整数点数）、两人之间的同项占比（精确到 0.1%）及实时排名变化。条形伸缩与名次换位应平滑、容易跟踪，榜单避开关键游戏信息。

每人统计的是其对**所有敌方英雄**的输出及所受英雄伤害，不限于长生与向鱼互相造成的伤害。不计小兵、野怪、防御塔或水晶的伤害，不把回复计作伤害。阵亡后切到队友观战时，不能把队友的伤害记在原选手名下。

占比为个人该项累计值除以两人该项累计值之和，**不是各自的队内占比**；两人均为零时均显示 0.0%。按点数降序排名，同分按长生、向鱼排列。

请将官播解说与两路画面对齐，以官播解说作为大屏主声道，关闭两路录像自带音轨，避免重复解说或回声。在大屏底部增加随解说更新的**战况／解说重点字幕**，准确保留解说中的关键事实，可压缩口头重复，不要补写未出现的判断。

当解说强调长生或向鱼的关键操作、失误或团战贡献时，结合实际画面判断对应选手，**同步高亮其第一视角窗口**。涉及两人时可以同时高亮；只谈其他选手、泛谈局势或指代无法确定时，不要强行高亮。

高亮使用清晰的描边或等效标记，保留窗口内关键游戏信息。重点话语开始后及时触发，话语结束后恢复普通状态，不能全程常亮。解说可能晚于操作发生，须分别记录话语与操作的时间，不要为了凑同时而改写解说或移动画面中的操作。

## 交付物

- `submission/dashboard.mp4`：至少 1920×1080 的完整有声复盘大屏。
- `submission/timeline.json`：驱动双榜的累计时间轴及终场汇总。
- `submission/commentary.json`：实际呈现的重点字幕、高亮区间及对应操作证据。

`timeline.json` 格式如下：

- 根对象包含 `points` 和 `final`。
- `points` 为按时间严格递增排列的记录数组；每条记录包含 `t_s`（长生录像的播放秒数）和 `players`。
- `players` 恰好以 `changsheng` 和 `xiangyu` 为键，每人包含 `damage_dealt` 和 `damage_taken` 两个非负整数。
- 第一条在 0 秒，两人的两项累计均为 0；各项累计不得下降，所有时间戳须小于长生输入录像的实际时长。
- `final` 为终场两名选手的 `players` 对象，须与最后一条记录一致，片尾双榜与其一致。

`commentary.json` 与成片一致，所有时间均以长生录像播放时间为基准：

- 根对象包含 `subtitles` 和 `highlights` 两个数组。
- `subtitles` 每条包含 `start_s`、`end_s`、`text`，表示实际显示的字幕区间和文字；记录按开始时间排序，不重叠。
- `highlights` 每条包含 `start_s`、`end_s`、`players`、`subtitle_index`、`event_start_s` 和 `visual_evidence`。
- `players` 为 `changsheng`、`xiangyu` 中的非空数组，列出该时段实际高亮的窗口，不得重复；`subtitle_index` 指向相应字幕（从 0 开始）。
- `event_start_s` 为画面中对应操作的发生时间；`visual_evidence` 简要说明哪个选手、在画面中做了什么，以支持解说指代的判断。
- 所有区间须满足 `0 ≤ start_s < end_s ≤ 成片时长`。字幕文字、高亮对象和起止时间均须在成片中实际呈现，不能只填写 JSON。
