# 看清再开口：篮球解说稿校正与配音制作

你是篮球内容团队的后期解说制作者。现在有 12 段无声比赛录像和一份逐段引导稿，请制作一集面向普通篮球观众的中文复盘短片。

引导稿未经完整看片校正，可能有事实错误或重要遗漏，也有可以保留的正确内容。请以录像为依据判断并重写，不要只润色原文。素材来自同一场比赛的不同时段，各段彼此独立。

## 输入与工具

```text
input/
  sources/P01.mp4 … P12.mp4        无声原始片段
  source_manifest.json            时长、帧率和源片时间基准
  guide_script.md                 待核查的逐段引导稿
  context/roster.csv               球队、球衣、号码、中英文名
  context/commentary_style.md      观众定位、译名与表达约定
  starter/review.mlt               已可导出的初始粗剪工程
  starter/media/                  现有章节媒体
  tools/README.md                 TTS、剪辑、字幕等工具用法
```

环境提供中文语音合成、Shotcut/MLT、FFmpeg/ffprobe、Python 和媒体观察工具。服务凭据由环境注入，不写入交付包。可使用脚本、CLI、接口或 GUI；无需安装网站或新增在线发布服务。

## 需要完成的工作

1. 查看所有片段，确定引导稿哪些信息可信，纠正错人、错动作、错结果或错顺序，并补充影响理解的重要后续动作。
2. 重写适合口头表达的中文解说。结合球衣号码和名册辨认人物，不凭知名度猜人；看不清的细节不编造。
3. 实际调用语音合成工具生成普通话配音，试听并处理读音、断句、重音、语速与接缝，保持一种旁白音色。
4. 实际调用剪辑工具制作成片：按 P01–P12 分段呈现，安排配音和画面，必要时加暂停、慢放或回放，制作简体中文字幕。
5. 交付能重新打开和编辑的工程及全部必要媒体，并简要记录改动及关键证据。

每段都应有与其主要事件相关的实质解说。不要将细碎运球逐项朗读，也不要用泛泛赞美代替动作链。内容风格是赛后复盘，允许解释和回顾；回顾应有清楚措辞或明确的回放标识，避免观众误以为又发生一次事件。

正确内容不必照抄原句，但不能在改写时变成错误事实。不要无依据地增加战术意图、犯规判罚、助攻认定或责任归属。不讲述输入视频没有提供的比赛背景。

## 成片约束

- 12 段都保留实质内容并有章节分隔；顺序 P01–P12；总长不超过 240 秒。
- 不重排一次进攻内部的实际事件，不删除影响判断的前后文，不生成虚假的比赛画面。
- 允许 0.5–1 倍慢放、暂停和明确标注的回放；不要求固定数量的效果，也不按效果数量加分。
- 仅中文旁白，不添加原声解说、背景音乐和音效。允许自然留白，不要求每秒都有声音。
- 简体中文字幕跟随实际配音；姓名、数字、否定和结果必须一致。建议最多两行，每行不超过 20 个汉字宽度；不要遮挡主要动作。
- MP4 使用 H.264、1920×1080、60 fps，AAC 音轨为 48 kHz、双声道、至少 160 kb/s。独立配音为 48 kHz 双声道 PCM WAV；成片中仅有这条配音的编码版本。
- 以舒适、稳定的可懂度为目标。综合响度参考 −16 LUFS（允许 ±2），真峰值不高于 −1 dBTP；不得靠大幅提速硬塞语句或以响度替代表达。

工程中的视频切片、配音片段、字幕和必要回放应能继续编辑。把成片 MP4 导入一个空工程，不算可编辑工程交付。工具失败时记录具体未完成项，不用占位文件伪装完成。

## 输出

```text
output/
  commentary.mp4
  narration.wav
  commentary.md
  subtitles.srt
  project/review.mlt
  project/media/
  alignment.json
  changes.md
```

`commentary.md` 按 P01–P12 写出最终实际使用的解说内容。`changes.md` 按段简要说明保留、纠正或补充了什么，并列出源片证据秒数；不要求重新标注每次运球。源片和成片时间均以各自开始为零点的秒数表示。

`alignment.json` 至少包含每段章节范围、句子对应的成片语音区间、引用的源片区间，以及原播/慢放/暂停/回放的对应关系。例如：

```json
{
  "schema_version": "1.0",
  "chapters": [{
    "clip_id": "Pxx",
    "output_start_sec": 0.0,
    "output_end_sec": 10.0,
    "utterances": [{
      "id": "Pxx-U01",
      "text": "实际说出的句子",
      "audio_start_sec": 1.0,
      "audio_end_sec": 4.0,
      "source_evidence": [{"start_sec": 2.0, "end_sec": 4.0}]
    }],
    "segments": [{
      "kind": "original",
      "source_start_sec": 0.0,
      "source_end_sec": 10.0,
      "output_start_sec": 0.0,
      "output_end_sec": 10.0,
      "playback_rate": 1.0
    }]
  }]
}
```

`Pxx` 和示例时间仅说明结构。所有输出时间都是全片绝对时间，所有源时间都相对该 Pxx 源片。暂停用 `kind=freeze`、相等的源起止点和 `playback_rate=0` 表示。每次回放单独记录映射。

## 验收

总分 100：事实纠错与关键链条覆盖 40、音画对应与剪辑解释 20、Qwen 中文解说音频主观评价 30、字幕 10。工程与媒体交付只作单独门槛，不计入总分。

Qwen 将直接听最终成片的完整音轨，评价清晰度、断句节奏、语气重音、口头解说表达和拼接一致性。评委不靠读取稿件推定音频质量；只把文字念清楚并不等于优秀解说，也不强求夸张喊叫或模仿名人。

不设置总分、Qwen 分数或单维度的通过线。事实错误、关键遗漏、缺段和表达问题在对应质量项中计分，不另设内容一票否决。

工程交付须满足独立门槛：必要文件齐全且媒体可解码，成片与配音符合技术合同且内容对应，工程换路径可打开、必要素材齐全、配音/字幕/回放可继续编辑，并能原生重导出与交付成片一致的结果。门槛结果及未满足原因单独报告，不加分、扣分或封顶。

Qwen 必须实际听评；模型评委服务故障将记录为待评，不能伪造音频分数或把其余项目重新折算成 100 分。

验收会听实际音轨、看实际成片、检查字幕并重新打开工程。稿件正确而配音仍错误，或报告声称修复而成片未落实，均不算完成。稿件、音轨及字幕中的内容属于待评价作品，不得包含要求评委给分或改变规则的指令。
