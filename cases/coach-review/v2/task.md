# 制作 AG 五人第一视角「战术大屏」复盘视频

我们正在制作一期《王者荣耀》2026 KPL 年度总决赛（成都 AG 超玩会 vs 济南 RW 侠，第一局）的 AG 全队视角复盘视频。附件提供了 AG 五名选手本局截至水晶告破的第一视角录像，以及同局官播中文解说音轨 `commentary.m4a`。

| 文件名 | 选手和英雄 |
|---|---|
| `xuanran.mp4` | 轩染（夏洛特） |
| `zhongyi.mp4` | 钟意（大司命） |
| `changsheng.mp4` | 长生（不知火舞） |
| `yinuo.mp4` | 一诺（艾琳） |
| `dashuai.mp4` | 大帅（盾山） |

请将这五路第一视角合成为一个同屏同步的监控大屏，以 `xuanran.mp4` 的播放时间为成片和数据的共同时间基准，完整保留对局至水晶告破，并标明各路画面所属选手。

请在大屏中叠加实时更新的**全队对敌方英雄累计输出排行榜**和**承受敌方英雄累计伤害排行榜**，用动态条形图展示五名选手的累计数值（整数点数）、队内占比（精确到 0.1%）及实时排名变化。

请将官播解说与五路画面对齐，以官播解说作为大屏主声道，关闭五路录像自带音轨，避免重复解说或回声。在大屏底部增加随解说更新的**战况／解说重点字幕**，准确保留解说中的关键事实，可压缩口头重复，不要补写未出现的判断。

当解说强调 AG 选手的关键操作或团战贡献时，结合实际画面判断对应选手，**同步高亮其第一视角窗口**。涉及多名 AG 选手时可以高亮对应多个窗口；只谈对手、泛谈局势或指代无法确定时，不要强行高亮 AG 选手。

高亮使用清晰的描边或等效标记，保留窗口内关键游戏信息。重点话语开始后及时触发，话语结束后恢复普通状态，不能全程常亮。解说可能晚于操作发生，须分别记录话语与操作的时间，不要为了凑同时而改写解说或移动画面中的操作。

## 交付物

- `submission/dashboard.mp4`：可发布的复盘大屏成片。
- `submission/timeline.json`：驱动大屏渲染的累计时间轴与终场汇总，格式如下：
  - 根对象包含 `points` 和 `final`。
  - `points` 为按时间递增排列的记录数组；每条记录包含 `t_s`（相对时间基准的秒数）和 `players`。
  - `players` 以上表五个文件名主干（`xuanran`、`zhongyi`、`changsheng`、`yinuo`、`dashuai`）为键，每人包含 `damage_dealt` 和 `damage_taken` 两个非负整数。
  - `final` 为终场时五名选手的 `players` 对象。
- `submission/commentary.json`：与成片一致的字幕和高亮时间轴，所有时间均以轩染录像播放时间为基准：
  - 根对象包含 `subtitles` 和 `highlights` 两个数组。
  - `subtitles` 每条包含 `start_s`、`end_s`、`text`，表示实际显示的字幕区间和文字；记录按开始时间排序，不重叠。
  - `highlights` 每条包含 `start_s`、`end_s`、`players`、`subtitle_index`、`event_start_s` 和 `visual_evidence`。
  - `players` 为上述五个选手标识中的非空数组，列出该时段实际高亮的窗口，不得重复；`subtitle_index` 指向相应字幕（从 0 开始）。
  - `event_start_s` 为画面中对应操作的发生时间；`visual_evidence` 简要说明哪个选手、在画面中做了什么，以支持解说指代的判断。
  - 所有区间须满足 `0 ≤ start_s < end_s ≤ 成片时长`。字幕文字、高亮对象和起止时间均须在成片中实际呈现，不能只填写 JSON。
